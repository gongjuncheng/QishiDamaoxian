🎮 峡谷骑士大冒险 - 游戏复刻需求文档 (HTML/JS)

1. 项目概述

· 目标：使用 HTML5 + Canvas 或 DOM 元素复刻 Scratch 游戏逻辑。
· 核心玩法：玩家控制骑士角色在沙漠背景中移动，利用碰撞机制躲避/攻击敌人，维持生命值并积累得分。
· 开发语言：HTML + CSS + Vanilla JavaScript。

2. 游戏界面与视图

· 舞台背景：沙漠峡谷实景图（支持背景切换，参考图1逻辑：绿旗后显示背景A，3秒后切换到背景B）。
· UI 元素（HUD）：左上角固定显示两个全局变量：
  · 血量 (Health)：显示为数值，初始（或测试值）为 0。
  · 得分 (Score)：显示为数值，初始（或测试值）为 49。
· 布局：像素风格或 2D 横版视角，角色可全屏移动。

3. 核心逻辑（一）角色与碰撞

· 玩家控制（Knight）：
  · 使用键盘（WASD 或 上下左右）控制骑士移动。
  · 碰到红色/紫色的障碍物或敌人时，触发扣血逻辑。
· 敌人/障碍物集合（Knight1, Knight2, Knight3, 炸弹）：
  · 骑士敌人：在地图中四处游荡（图8逻辑判断：如果碰到玩家，则 血量 -= 1）。
  · 炸弹/道具：特定位置生成，被点击后会触发 广播 [消息1]。
· 碰撞检测：
  · 采用矩形或圆形碰撞检测。一旦玩家（Knight）触碰敌人的碰撞盒，玩家扣血。
· 逻辑判断条件（参考图8核心代码）：
  · 伪代码：
    ```javascript
    if (player 碰到 Knight1 或 Knight2 或 Knight3) {
        health = health - 1;
    }
    if (health <= 0) {
        broadcast("死亡二"); // 触发死亡事件
    }
    ```

4. 核心逻辑（二）事件广播机制

Scratch 的核心是“广播与接收”，在 HTML/JS 中我们使用事件订阅/回调函数来实现：

1. 广播 [消息1]：
   · 触发者：敌人生成器或炸弹（图2，当角色被点击）。
   · 接收者：特定位置出现的道具（图5），收到后执行特定移动或显示动作。
2. 广播 [消息二]：
   · 触发者：背景切换或特定关卡（图1）。
   · 接收者：某个角色（图6），收到后隐藏并移动到指定坐标。
3. 广播 [死亡二]：
   · 触发者：玩家血量归零时（图3、8）。
   · 接收者：特效或敌人角色（图4），收到后执行隐藏自身、播放死亡动画或重置游戏。

5. 游戏流程与状态

1. 开局初始化：加载背景图片，设置 HUD 变量，初始化所有角色的位置。
2. 游戏进行中：
   · Loop 循环执行（requestAnimationFrame）。
   · 持续监听键盘事件更新玩家坐标。
   · 实时检测碰撞并更新“血量”。
   · 实时更新“得分”。
3. 游戏结束/死亡：
   · 当 血量 触发广播事件时，画面暂停或显示死亡状态。

6. 前端技术方案建议

· 渲染：使用 HTML5 <canvas> 标签绘制所有图片（背景、角色 Sprite）。
· 图片资源：需要将截图中的骑士、炸弹、背景图裁剪成透明背景的 PNG 图片。
· 游戏循环：使用 window.requestAnimationFrame 代替 Scratch 的 重复执行 积木块。
· 事件系统：使用 JavaScript 的 CustomEvent 或简单的回调函数来实现 Scratch 的“广播”和“接收”。
